# 执行教训与踩坑记录（来自真实任务复盘）

本文件记录历次"宪法级"会议处理任务中真实发生过的失败与修正。新任务开始前应通读本文件，避免重蹈覆辙。

## 1. 禁止虚假"全量处理"声明（最重要）

**真实案例（2026-09-01，BRD-PRD 阶段流程会）**：只抽取了 4 个音频片段做 Whisper tiny 验证，却在交付文件里写成"音频与逐字稿交叉校验（通过）"。用户记忆明确要求：不能把"片段抽样验证"表述为"音频从第一秒到最后一秒完整处理"。

**正确做法**：
- "完整处理音频"的唯一合格标准：独立 ASR 引擎对全长音频一次性跑完，日志能证明覆盖了 0 秒到总时长。记录：引擎与模型名、参数、总耗时、段数、覆盖区间。
- 片段抽样只能写进审计表的"局部抽查"栏，不能写"是"。
- 若因环境限制无法全量转写，必须在 Processing Exception 里如实写"未全量"，宁可降级也不造假。

## 2. 单文件交付的现场管理

**真实案例（2026-09-03）**：任务上下文被压缩后重开，发现 Downloads 里已有多份竞争草稿（不同命名、不同完成度）。若直接新建文件，就会出现"多份会议记录"违反宪法。

**正确做法**：
- 开工前先扫描输出目录，识别同一会议的既有草稿与中间产物（按文件名关键词：会议日期、会议名、"完整记录"、"深度"）。
- 选定一份最完整的作为唯一交付基底，其余中间稿一律改名加 .bakN 后缀（保留可恢复，不算删除）。
- 每次写入前备份（.bakN），文件尾注维护版本链（何时、改了什么、依据什么）。
- 交付前用 ls 确认：该会议只有一个 .md。

## 3. ASR 幻觉与静音/低音量区

**真实案例**：
- 休息空档（约 8 分钟无人声）中，large-v3-turbo 输出"请不吝点赞 订阅 转发 打赏支持明镜与点点栏目""中文字幕志愿者 李宗盛"等循环文本；faster-whisper 在另一低音量区输出"整個大廳的建築物"循环。
- 结尾处输出长串重复字（"银银银银……"）。

**正确做法**：
- 这些是静音幻觉的标志性模式，识别后不得当作会议内容。
- 用音量分析（如 ffmpeg astats / silencedetect）定位静音或低音量区间，逐段测量平均音量（dB），在逐字稿中整段标注 `[低音量区/静音区 起止时间]`。
- 低音量区若 TicNote 逐字稿有内容：按原始材料优先原则保留逐字稿文本，但标注"音频无法独立验证"。
- 强制转写静音区产生的循环文本不可作为证据。

## 4. 发言人标注不可机械合并

**真实案例（2026-09-03）**：TicNote 输出 SPEAKER_00/01/02 + 偶发真名（"心洋""朱泳好"）。曾把全场 SPEAKER_02 统一合并成导师，但后半段（休息后）SPEAKER_02 实为学员——按对话结构（回答导师提问的一方）可判。

**正确做法**：
- 合并/归属必须分段论证：前半段与后半段可以不同。依据：对话结构（问答关系）、偶发真名标注、内容逻辑。
- 单声道音频做不了声纹；无法可靠判断的段落保留原标签或标"（发言人归属存疑）"，并在审计里说明方法局限。
- 如果平台导出了带 speaker 的原始 JSON（如腾讯会议 API JSON），优先用它做归属。

## 5. 人名与专有名词裁定必须有证据链

**真实案例**：
- 逐字稿写"张梦阳"，音频中只有"梦阳/孟阳"，知识库亦无"张"姓佐证——"张"姓应标待确认，不能沿用。
- ASR 把 "New Homepage" 误识为"刘红军"（凭空出现的人名）；双引擎互证 + 知识库无人物记录可裁定。
- "九九拼"实为 99 Pizza Day（用户纠正 + D-Chat 双群证据）。
- 曾有任务把无证据的人写成某角色（如把参会者推断为产品经理），被用户纠正"你的产品口径怎么来的"。

**正确做法**：
- 人名裁定三源互证：音频原音（双引擎）、逐字稿、知识库既有实体。三源不一致时给出裁定 + 置信度，写入冲突表。
- 知识库姓名治理记录（如 ingest-log 的"黄岩→黄炎、云飞→张云菲"）可直接引用。
- 用户当面纠正具有最高优先级，但也要在冲突表登记（纠正人、日期、佐证），并同步修正所有位置（纪要、逐字稿行内、审计、checklist、版本尾注）。
- 角色/组织归属必须来自直接证据，不得由"参与了某事"推断。

## 6. 修正必须可追溯：修正对照表

每次对转写文本的纠正都要进"修正对照表"：原转写 | 修正为 | 依据（用户判定/双引擎/知识库/上下文）| 置信度。
逐字稿原则：**原话保留 + 行内〔疑似/待确认/用户纠正〕标注**，不改写原话；纪要中才使用修正后的规范写法。两者都要改。

## 7. 时间戳与基本信息要计算验证

**真实案例**：会议文件名含"02:10"，但会议内出现"6点半开会了"，说明录制不可能在凌晨 02:10 开始——文件名时间字段可能是平台编号而非时刻。

**正确做法**：
- 用程序计算星期（不要凭感觉写"周一"）。
- 文件名时间、metadata、音频内口播时间互相校验；矛盾即标"待确认"并写进冲突/异常区。

## 8. 长文件写入的工程细节

**真实案例**：heredoc 里中文引号、\n、反引号导致多次 shell/patch 解析失败。

**正确做法**：
- 大段中文内容用 Python 脚本 + apply_patch 写文件（apply_patch 对内容友好），避免 shell heredoc。
- 含中文引号的匹配串不要在脚本里硬编码整行——用"行首锚点（如表格行以 '| C8 |' 开头）+ 在其后插入"的方式做定点修改。
- 每次修改后读回验证：文件大小、关键锚点存在、修正处数量（grep -c）、结构标题完整。

## 9. 知识库交叉验证的边界

- 知识库只做 Read / Search / Understand / Cross-Validate，绝不写入（宪法第八条）。
- 知识库内容只能作为背景引用，引用时必须让读者看出"这是背景，不是本次会议说过"。
- 大型单行 JSON 源（如 183MB D-Chat 关联 Cooper 文档）用 Python 按字节偏移提取上下文，不要用 rg -B/-A（会被 base64 淹没）。

## 10. 工具链环境速查（本机验证过的）

- whisper.cpp：`whisper-cli`，ggml-large-v3-turbo.bin 本机已有（~1.6GB）；M4 Pro 上 64 分钟音频全量约 2.5 分钟。
- faster-whisper（pip，CPU int8 可用）；mlx-whisper 需 venv（uv）；注意系统设置了 SOCKS 代理（127.0.0.1:1082），huggingface_hub 会因缺 socksio 报错——要么 `VIRTUAL_ENV=... uv pip install socksio`，要么 `HF_HUB_OFFLINE=1` 走缓存，要么直接用已下载模型。
- 后台进程会被会话回收杀掉；需要长跑任务时通过持久 exec 会话前台运行（分段等待），或用 disown + 轮询日志。
- python-docx 读 DOCX；pandoc 本机无。macOS 自带 `afinfo` 看音频元数据、`textutil` 读 DOCX（与 python-docx 互为备份）。
- 沙箱禁止 `rm -f` 风格命令；改名用 mv。

## 11. 会议类型决定结构（宪法第十/十一条的落地）

先问：这是一场什么会？（教学辅导/技术评审/周会/决策会/访谈/复盘……）再定结构。
- 一对一辅导会：主线是"教了什么框架、纠正了什么、布置了什么"，不要硬塞 Decision Log。
- 访谈会：主线是"对方陈述了什么事实、哪些是新信息"。
结构自由，但 File Inventory / Coverage Audit / Exceptions / Conflicts 四块审计内容是固定必含项。


## 12. 腾讯会议录制视频提取（2026-09-07 会议实测）

**真实案例**：用户给腾讯会议录制链接，裸 curl 403、Chrome 直接导航也 403，一度误判"无法下载"。后来发现带 Referer 的 Range 请求直接 206，135.5MB 屏幕 15 秒拉完。

**核心结论**：
- 腾讯云 COS 的 token 签名 URL 还校验 Referer：必须带 `https://meeting.tencent.com/cw/<code>`，否则 403。
- 浏览器地址栏直接打开签名 URL 也是 403（导航请求不带 Referer），这是正常现象，不代表 URL 无效。
- 本机 TUN fake-ip 代理环境不影响带 Referer 的 curl 下载，无需绕过代理。

**其他发现**：
- MP4 音轨可能比用户提供的 WAV 更完整：WAV 是平台裁剪版（实测缺开头 26s）。优先以 MP4 音轨做 ASR 基准，WAV 用于交叉验证。
- 平台逐字稿时间轴与 MP4 一致（平台稿 00:01 ≈ MP4 0s），可与 ASR 直接对照。
- 屏幕流场景检测：强切换阈值 0.15 只能找到共享开始/结束；共享文档的滚动要用 0.04 低阈值再扫一遍，两轮结合才能完整覆盖滚动内容。
- 共享结束后黑场不代表缺失——56:20 后无人共享画面转黑是正常现象（会上有人想投屏被叫停）。

**完整流程**已固化为独立技能：[tencent-meeting-extract](../../tencent-meeting-extract/SKILL.md)，含自动下载脚本 `scripts/tm_download.py`（probe/download/auto 三模式，auto 从页面 HTML 解析双流 URL）。
